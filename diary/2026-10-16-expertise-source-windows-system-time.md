# Expertise candidates, readable sources and a dated system view

This checkpoint keeps the CLI, shared services and bridge on the same evidence.
It adds ways to inspect the material already found rather than treating a label
or a running process as proof of a complete journey.

Living-expertise discovery reuses the native Hermes profile inventory and the
installed Starship/Starforge metadata detectors. Supported Compose/OCI identity,
an authored description and charter references make a candidate. The candidate
is a separate galaxy destination with exact implementation links; it does not
become owned by that product's client system. Missing descriptions stay incomplete
and automatic descriptions stay unconfirmed. Nothing is launched during discovery.

The review corrected selected Docker build-stage identity, launcher cache
invalidation, non-scalar profile metadata and default-charter qualification.
Inventory paging now isolates unreadable roots and excludes broad ancestor
context folders from project inspection. A replay reached all 329 eligible roots
in the 331-root inventory and found the Observatory through generic metadata.
Missing locations and a Compose parse limitation remained visible.

`atlas inspect` reads the recorded expertise dossier. A selected metadata refresh
persists for later inspection. Explicit process observation is a separate action
with a separate date and provider binding; it does not establish model readiness,
answer quality or permission to run an agent. Ship receiving/captain evidence keeps
its existing independent meaning.

`sources read` opens bounded, numbered windows from published snapshots. Original
paths are addresses only. Snapshot/generation pins reject stale result links,
and historical reads verify the pinned Git file hash. The source reader used the
actual cached NavCom artifact successfully without reading the current file.
Automatic intake now finds nested README and SOUL documents in the same bounded
Git-aware walk. Both missing Observatory documents were selected by the tool;
raw provider config was not added. The live dry-run also disclosed its Git-ignore
time limit rather than presenting partial coverage as complete.

`history system` keeps current system/galaxy addresses fixed while reconstructing
committed source at a UTC cutoff. It pins repository HEADs once, continues those
pins across cursor pages, and leaves missing or unvisited history unknown. Native
fixtures distinguish old product identities and password code from newer names
and Cognito code, exclude dirty current files, and retain pinned history after a
new commit appears. Current conversations are not attributed to those commits.

Decided: reuse the existing provider, harvest and historical services; keep
candidate metadata, process observations, source generations and Git revisions
separately attributable. Source-reader and time controls consume these services.
Help, the embedded/generated skill card and package allowlists describe the same
commands.

Not decided or claimed: historical ownership reconstruction, deleted products
absent from current addresses, automatic expert questions, new service starts,
verified ship boarding, or completion of the galactic goal. This entry does not
record a release or publication.

Browser proof now covers source paging, Back/Escape and a narrow screen without
overflow, an explicit star process observation, and old/new dated charts with a
slider and stable positions. The container was observed running; no expert
question or model-readiness check ran. The real Syra browser continued its pinned
repository pages. CLI continuation reached eleven of thirteen repository jobs
and nine of forty-two committed product addresses at this measurement; time and
file budgets leave the remainder unknown. A 60-second bounded retry did not
advance those counts. This is partial historical recovery.

The five help tests pass, including runnable examples in a temporary HOME and a
loopback browser check. The generated skill card matches its embedded source,
and both package allowlists include the new services. The combined regression
covered all 319 pytest cases, with socket-dependent tests rerun successfully
using local loopback permission. BDD passed 130 scenarios and 699 steps;
JavaScript syntax and diff checks passed. Package build and installation proof
remain a separate gate.
