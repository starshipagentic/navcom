# October 16 — Reach the apps inside a repository, and know which copy you see

The map was navigable, but a working product could still disappear inside a
larger repository. The real Syra case exposed the general problem: its current
mobile applications have runnable manifests but the repository root does not
declare workspaces. The decision is to preserve those nested manifests in bounded
automatic intake and ask existing Starforge entry/build detectors about them.
Neither a client profile nor manually synchronized source catalog is involved.

Candidate applications have exact source roots. Native conceptual grouping runs
within those scopes so a district cannot silently mix mobile and platform code.
Build/test-only packages do not qualify as runnable application candidates. The
candidate still does not prove ownership, runtime health or a separate product.

The local lab found both `apps/uapp-app` and `apps/universal` through ordinary
discovery and harvest. The mobile scope returned one native concept match and
twelve broader text matches for `push`, all inside the mobile application. A
second automatic harvest reused its snapshot without reanalysis. The live bridge
was updated through the same commands, not by copying that lab catalog.

The physical plane now has an initial practical control: `atlas inspect PLACE`
and **Inspect code locations**. They share a dated cache of filesystem and native
Git observations. Awali's three locations proved to be linked worktrees; RecipeDB's
three locations proved to be independent repositories, with distinct commits.
No preferred copy, succession, working-tree cleanliness or application runtime is
inferred. Explicit refresh reobserves the locations. Remote host paths remain
unobserved rather than being opened on this machine.

Flight improvements accompany this evidence work. Destination pages expose the
whole chart in bounded groups; Back preserves the earlier page and viewpoint.
Conversation paging retains its visible return control and restores the originating
search-card focus. Keyboard selection reaches Fly directly. Long voice transcripts
stay editable with a clear limit, without truncating speech or replacing existing
typing prematurely. Background refresh leaves an open dossier or history panel
alone, as it already does for a draft, reader or voice interaction.

EXP29's harvest timeout came from repeated native TinyDB serialization and a
duplicate completeness scan. Unpublished catalogs now use TinyDB's own buffering,
and one native scan is checked against what the native catalog stored. The actual
first grouped intake took 5.61 seconds; the separate cached invocation took 1.28
seconds and retained the same publication. An automatic source job containing its
own cache is now skipped with the existing containment reason before traversal.

Still undecided or incomplete: product-generation relationships, evidence linking
separate experiments, broader source coverage, real microphone capture, live
expert answers and visible captain takeover. Physical copy inspection does not
settle those questions. No other codebase or external release was changed.

The final catalog review caught duplicate app planets from overlapping ancestor
harvests. Native Git ownership now reconciles those candidates, retaining exact
older saved subtrees where present. Missing or substituted locations keep their
recorded owner and become unavailable; readable native evidence can revise it.
The live refresh produced one destination per exact nested application path.

Verification: the full regression run passed 499 tests, and BDD passed 130
scenarios / 699 steps. The subsequent ownership edge fixes passed 38 space tests
and four final continuity cases; independent worker/discovery checks passed 32.

byte-for-byte with the checkout and wheel. Installed CLI search returned one
concept and twelve text matches inside the exact mobile scope; physical inspection
identified the three Awali linked worktrees. The real browser flew into the mobile
planet, displayed its three districts and opened its physical-location dossier.
