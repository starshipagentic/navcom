## Decisions

- Starship's bridge evidence anchors its sibling archive; NavCom does not manually synchronize inventory or change a remote working ship's address.
- An archive is a ship form, not a new celestial kind. Its stored context remains readable; it cannot board a captain.
- Storage relationships do not establish product ownership, current readiness, integrity, or transcript membership.
- The galaxy overview stays conceptual. Stored copies remain explicit in its catalog, ship links, searches and typed CLI lists.
- Starforge's existing harvest/search remains the source-analysis engine. Native Git determines submodule ownership and ignore rules.

- Real microphone capture, expert responses, captain takeover and full inventory coverage still need their own proof.

## Source-reader return timing

The installed browser exposed one further race: closing a source reader starts
an asynchronous viewpoint restoration. A new Search submitted before that
restoration completed could be cancelled by its automatic evidence replay,
which had already lost the interpreted scope. The controller now checks its
original search generation before replaying, and never submits an unsent draft.
Four deferred-response regressions reproduce the old failure and verify newer
searches, Clear, unsent drafts, and ordinary scoped restoration. They passed
alongside 25 surrounding state/reader checks. The fix required only the browser
controller; no catalog changes or new search logic.
