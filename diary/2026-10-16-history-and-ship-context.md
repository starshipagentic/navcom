# History and ship context retain their source

The bridge was opened for the owner to fly. Work continues beneath the same CLI
and UI service; the galactic goal remains active.

Ship inspection is now a real `navcom atlas inspect` operation. It uses the
installed ship-commission metadata observer for explicit local locations and
discovers existing Starship receipts by record identity and exact physical root.
It never interprets a remote host's path as a local ship. A later supplemental
check and an earlier carried-history inventory remain separately attributed.
The actual NavCom ship yielded its captain viewpoint and 24 Claude sessions /
458 messages without copying a catalog entry by hand. The browser inspection,
refresh and leave/return journey passed, preserving the camera and cached dossier.
None of that establishes receiving readiness or captain takeover.

Automatic discovery now selects bounded code as well as documents, fairly across
declared application roots. Starforge's native token groups run within those
roots, so shared vocabulary cannot erase a declared application boundary. An
unfamiliar two-application fixture produced separate districts, found both code
and docs, and reused the second harvest. District conversation results explicitly
mean matching project context; they do not claim a proven file relationship.

`navcom history timeline` and `history explore` now read committed Git objects
into immutable, bounded snapshots and invoke the same Starforge harvest/search
worker. A two-date fixture distinguishes old password-login code and product
identity from new Cognito code; dirty current content stays out. The real NavCom
HEAD also passed both search paths. Review caught empty scopes that could widen
search and current symlink addresses that could redirect historical lookup;
these are regression cases, not acceptable fallback behavior.

Decided: preserve exact commit/tree, scope, tool identity, provenance and separate
evidence dates. Use historical manifests and native groups, not current labels as
historical facts. Keep current geography steady while inspecting a selected
repository's history. Cached browsing does not rerun harvest.

Still unfinished: whole-system time navigation across repositories, attributable
historical conversation joins, a declared living-star inventory and callable
interfaces, verified ship boarding/restored context, and actual local microphone
capture on this browser. No upstream Starforge/Starship source was modified and
no release was published in this checkpoint.

Final real intake caught and corrected a coverage defect: automatic discovery
was including ignored lab copies while omitting the 596 kB main NavCom file.
Native Git ignore decisions now govern automatic intake. Broad text search keeps
eligible files up to 2 MiB; the separate 250 kB grouping cap is explicitly
reported. The main file is searchable and its grouping omission is visible.
All 17 sources were reused on the next refresh (0.049 seconds in the worker),
and the installed CLI's repeated search hit the query cache.

The owner-facing bridge now uses the real existing index, not the early bounded
preview database. NavCom's own CLI refreshed 6,619 placed conversations across
331 project roots; full text search reaches the existing 687,873 indexed turns.
No catalog rows were copied by hand. The bridge stayed at the same URL and
retained the galaxy viewpoint after the necessary server reload.

Validation: 255 pytest tests, 130 BDD scenarios / 699 steps, then 14 targeted
source/history tests for the final coverage disclosure. The local 0.10.0 wheel
was built, compared against checkout bytes and installed in the existing pipx
environment. Installed history and ship inspection commands work. UI History
and ship inspection journeys passed in a real browser, including Back, reload,
keyboard and a 390px viewport; whole-system time travel and ship takeover are
still separate unfinished requirements.

Full-archive browser proof: EXP32 followed by local `matrix` returned 32 code/doc
hits and 13 conversations. Back retained query, scope, selected moon, camera and
node positions; no console errors. The wider archive exposed a UI truncation:
26 reported conversation results had only 20 reachable cards. Results now show
six initially and expose every remaining returned card through a disclosure.
Narrow-screen selection brings the Fly control into view, and explicit flight
returns to the destination chart. Keyboard Enter was verified through that flow.
